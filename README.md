# 通用高风险分录（HRC）筛查模板

> 本仓库是一份**通用、已脱敏**的 T-SQL 高风险分录（High-Risk Classification，HRC）筛查模板。
> 它源自一份客户专属的审计分析脚本，已移除全部客户标识、真实公司代码、真实科目与人员信息，
> 仅保留**可复用的审计方法论与筛查逻辑框架**，可直接在标准 SQL Server 上基于合成数据运行与自测。

---

## 1. 方法论：HRC 三类高风险分录

模板按三类（可扩展）高风险特征对日记账分录（journal entries）进行筛查：

### HRC1 — 手工分录（Manual Entries）
由人工录入、而非系统自动过账的分录，重点关注两类：

- **HRC1.1 贷方含收入的手工分录**：借贷标识为「贷方(H)」、总账科目为收入类（`60` 开头）、且由批处理/数字用户名（`WF-BATCH`、`SAP_WFRT`、纯数字用户名）编制的分录。
- **HRC1.2 借方含生产成本的手工分录**：借贷标识为「借方(S)」、总账科目为生产成本类（`5001` 开头）的手工分录（通用变体要求项目文本含特定关键词，特殊公司变体仅按科目判定）。

**动态调整**：当命中数量较少时直接输出完整凭证；数量较多时按关键词（如「错误/冲销/调差/调整」）、再按「客商编号仅出现一次」逐级收紧，控制抽样规模。

### HRC2 — 异常会计处理（Abnormal Postings）
利用**差集运算**识别违背会计勾稽关系的分录：

- **HRC2.1 收入贷记但未借记对应资产**：存在贷记收入的分录，但同一凭证未借记应收账款、预收账款、应收票据、职工薪酬、现金或银行存款等对应资产/债权科目。
- **HRC2.2 利息收入贷记但未借记对应资产**：贷记利息收入（`660302` 开头）但未借记应收利息、其他应收款、现金或银行存款等对应资产科目。

**可配置排除规则**：部分公司需按账号前缀（如 `E`/`B` 开头）或剔除「集团内往来」描述的分录——此类「按公司代码的特殊排除规则」已改写为**可配置列表变量**（见 `hrc_screening.sql` 配置区），而非硬编码。

### HRC3 — 特定人员编制（Key-User Entries）
由关键岗位人员名单（如业务总监）编制的全部分录，用于关注非授权或重点人员操作。

## 2. 表结构要求

筛查对象为一张通用日记账分录表 `dbo.journal_entries`（字段已脱敏、通用化）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `voucher_no` | VARCHAR(50) | 会计凭证号码（主键维度） |
| `company_code` | VARCHAR(10) | 公司代码（通用占位 `C001..C00N`） |
| `dr_cr_indicator` | CHAR(1) | 借贷标识：`H`=贷方，`S`=借方 |
| `gl_account` | VARCHAR(20) | 总账科目代码 |
| `account_desc` | NVARCHAR(200) | 科目描述 |
| `username` | VARCHAR(50) | 创建人用户名 |
| `voucher_date` | DATE | 凭证日期 |
| `item_text` | NVARCHAR(500) | 项目文本/分录描述 |
| `amount` | DECIMAL(18,2) | 按本位币计的金额 |
| `customer_no` | VARCHAR(50) | 客户/客商编号 |
| `customer_name` | NVARCHAR(200) | 客户/客商名称 |
| `fiscal_period` | INT | 会计期间（1–12） |
| `voucher_status` | CHAR(1) | 凭证状态：`D`=已删除（筛查时排除） |

> 原始源表使用中文列名与 SAP 表（BKPF/BSEG/SKAT/KNA1/LFA1）；本模板统一为通用英文列名，
> 并在 `setup_and_check.sql` 中给出建表与索引示例。

## 4. 使用方式

1. 在 SQL Server 中运行 `setup_and_check.sql`，创建 `dbo.journal_entries` 与索引。
2. （可选）运行 `examples.sql` 插入合成数据以自测。
3. 打开 `hrc_screening.sql`，在 **配置区** 按需填写：
   - 待筛查公司清单 `@company_list`
   - 跳过清单 `@skip_list`
   - 各类可配置排除列表（账号前缀、集团内往来、长期应收款、利息收入自抵等）
   - 关键人员名单 `@key_user_list`
   - 科目前缀参数（`@rev_prefix`、`@cost_prefix`、`@interest_prefix` 等）
4. 执行脚本，查看 `#HRC_Summary`（按公司汇总的各 HRC 描述）与 `#HRC_Detail`（命中凭证明细）。

> ⚙️ **须用户自行配置的点**：`@company_list`、`@key_user_list`、各排除列表与科目前缀均为占位示例，
> 部署到真实环境前必须按被审计单位的科目表与组织口径替换。

## 5. 性能建议

- 在 `company_code`、`voucher_no`、`fiscal_period`、`username`、`gl_account` 上建立索引（见 `setup_and_check.sql`）。
- 大数据量（百万行级）建议按月分区或按公司代码分批运行。
- 逐公司循环（游标）便于应用「按公司特殊规则」；若规则一致，可改写为集合式（set-based）查询以并行提速。
- 导出结果可用 `bcp` / SSIS / `OPENROWSET`，路径请使用相对路径或注释说明，勿硬编码绝对路径。

---

## 6. 合规与脱敏说明

- 本模板**不含任何客户数据**：已移除原客户名称、真实公司代码、真实内部科目（如原长期应收款类科目）、真实人名/账号。
- 真实公司代码 → 通用占位 `C001..C00N`；真实内部科目 → 通用「应收类科目」示例（以 `1122`/`1999` 等占位示意，非真实科目）；人员名单 → 示例占位 `U0001..`。
- 原脚本中的硬编码「按公司特殊排除规则」已重构为**可配置列表变量**演示，便于复用而不泄露客户特定逻辑。
- 原有的绝对路径已统一改为相对路径或注释。
- 本模板仅提供方法论框架，应用于真实审计前须由审计人员按所在机构标准复核与配置。
